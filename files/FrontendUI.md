# Design Prompt: Ollama Agent Workspace Interface

## Project Overview
Design a desktop application interface for an AI agent workspace system. This is a development tool that gives local Ollama models (specifically Gemma) persistent memory and file management capabilities, with intelligent background maintenance by cloud AI models.

## Core User Experience

### Primary Interface: Chat-First Design
The main interaction is a **chat interface** where users talk to their local AI agent (Gemma). The agent can search, read, and write files in its workspace while responding.

### Key User Flows

**1. Starting a New Project**
- User clicks "New Project" 
- Modal appears with:
  - Project name input
  - Optional description
  - "Base Knowledge" selector (checkboxes for documents/folders to include)
  - "Create Project" button
- Project workspace is created and chat begins

**2. Ongoing Conversation**
- User types message in chat input
- Agent responds (may take a moment while searching files)
- Below agent's message, show "Tool Activity" (collapsible):
  - "🔍 Searched workspace for 'authentication patterns'"
  - "📄 Read: `/auth/strategy.md`"
  - "✏️ Created: `/notes/session_notes.md`"
  - Each with timestamp
- User can click on filenames to open them in side panel

**3. File Management**
- Split view: Chat (60%) | File Browser (40%)
- File browser shows:
  - Current project directory tree
  - Files with icons by type
  - Hover shows file summary (generated by cloud model)
  - Click to open in viewer/editor
  - Right-click context menu: rename, delete, move

**4. Background Activity Notifications**
- Subtle notification badge: "Workspace analyzed"
- Click to see maintenance agent's suggestions:
  - "💡 Suggestion: Merge these 3 similar files?"
  - "⚠️ Outdated: `api_v1_notes.md` references old version"
  - "✨ README updated with recent changes"
- User can accept/dismiss suggestions

**5. Timeline/History View**
- Accessible via tab or sidebar toggle
- Shows chronological breadcrumb trail:
  ```
  2:30 PM - Researched authentication patterns
            Files: read strategy.md, wrote oauth_notes.md
  
  2:45 PM - Implemented login flow
            Files: created login_handler.py
  
  3:00 PM - Checkpoint: Auth system design complete
  ```
- Can click timestamps to see chat context from that moment
- Filter by file, topic, or date range

## Interface Components

### Top Bar
- Project dropdown (switch between projects)
- Project name (editable inline)
- Settings icon
- Workspace health indicator (green/yellow/red dot with tooltip)

### Main Chat Area
- Clean, minimal chat interface
- Agent messages can include:
  - Text responses
  - Code blocks (with syntax highlighting)
  - File links (clickable)
  - Tool usage indicators (collapsible details)
- Input area with:
  - Text input (supports multiline with Shift+Enter)
  - File attachment button (add documents for agent to process)
  - Send button

### Side Panel (Toggleable)
**Tabs:**
1. **Files** - Directory tree browser
2. **Search** - Semantic search across workspace
3. **Timeline** - Breadcrumb trail view
4. **Insights** - Maintenance agent suggestions

### File Viewer/Editor
- Opens when clicking file in browser or chat
- Shows in modal or replaces side panel
- Features:
  - Syntax highlighting for code
  - Markdown preview
  - Edit capability (saves trigger re-embedding)
  - File metadata: tags, last modified, summary

### Project README Dashboard (Optional home view)
- When opening a project, option to show README first
- Contains:
  - Project overview
  - Topic index (links to relevant files)
  - Recent activity summary
  - Quick actions: "Continue last session", "Start new task"

## Visual Design Preferences

### Style
- Modern, clean developer tool aesthetic
- Think VS Code meets ChatGPT interface
- Dark mode primary (light mode optional)
- Professional but not sterile

### Colors
- Background: Dark grey (#1e1e1e or similar)
- Chat bubbles: User (blue accent), Agent (subtle grey)
- Tool activity: Muted colors per action type (search=blue, read=green, write=orange)
- Syntax highlighting: Standard developer themes

### Typography
- Monospace for code, file paths
- Sans-serif for chat, UI elements
- Clear hierarchy (message text larger than metadata)

### Interactions
- Smooth transitions (no jarring jumps)
- Hover states on all interactive elements
- Loading indicators when agent is thinking/searching
- Subtle animations for file operations

## Special Features to Highlight

### Agent Activity Transparency
- Users should always see what the agent is doing
- Tool calls are visible but not intrusive
- Progress indicators for long operations

### Smart Suggestions
- Maintenance agent insights appear as non-blocking notifications
- Can be expanded to see reasoning
- One-click actions to accept suggestions

### Context Awareness
- Chat input shows "Current project: [name]" when multiple projects exist
- File browser highlights recently accessed files
- Search results show relevance scores

### Keyboard Shortcuts
- `/` to focus search
- `Cmd/Ctrl + K` for quick file open
- `Cmd/Ctrl + N` for new project
- `Cmd/Ctrl + Enter` to send message
- `Esc` to close modals/panels

## Technical Considerations

### Performance Indicators
- Show when local Gemma is responding vs when waiting for cloud maintenance
- "Analyzing workspace..." progress bar for background tasks
- Token usage meter (optional, for power users)

### Error Handling
- Graceful failures: "Couldn't read file, it may have been moved"
- Retry options for failed operations
- Clear error messages, no technical jargon

### Data Persistence
- Auto-save chat history
- Project state persists between sessions
- "Resume" functionality to continue where left off

## Example User Scenarios

**Scenario 1: Research Session**
1. User opens project "ML Paper Notes"
2. Chats: "Summarize the key points about transformers from my notes"
3. Agent searches workspace, reads 3 files, responds with synthesis
4. User sees tool activity, clicks on one file to read full context
5. Continues conversation, agent creates new synthesis file
6. Session auto-checkpoints, breadcrumb logged

**Scenario 2: Code Development**
1. User creates new project "API Redesign" with existing docs included
2. Chats about authentication approach
3. Agent reads base knowledge, suggests strategy, writes notes
4. Later, maintenance agent notifies: "README updated with auth decisions"
5. User reviews timeline to see evolution of design decisions
6. Continues implementation with agent

**Scenario 3: Knowledge Organization**
1. User has messy project with 50+ files
2. Opens Insights tab, sees maintenance suggestions
3. "Consolidate these 5 auth-related files?"
4. User accepts, agent merges with user confirmation
5. README automatically updates with new structure
6. Workspace health indicator turns green

## Design Goals
- **Transparency**: Users always understand what the agent is doing
- **Efficiency**: Fast access to files and history without leaving chat
- **Intelligence**: Surfacing maintenance insights without overwhelming
- **Familiarity**: Feels like a natural evolution of chat + IDE
- **Focus**: Chat remains primary interface, everything else supports it

Generate a complete UI/UX design for this system that balances simplicity with powerful functionality for developers who want their AI agents to have persistent, organized memory.
